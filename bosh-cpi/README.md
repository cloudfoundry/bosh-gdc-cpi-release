# BOSH GDC CPI

This directory contains the Go implementation of the [Cloud Foundry BOSH](https://bosh.io/docs/) Cloud Provider Interface (CPI) for Google Distributed Cloud air-gapped (GDC), enabling BOSH to provision and manage virtual machines, persistent disks, snapshots, networks, and stemcells on GDC.

## Prerequisites

### Create a Project

```sh
kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> apply -f - <<EOF
apiVersion: resourcemanager.gdc.goog/v1alpha1
kind: Project
metadata:
  namespace: platform
  name: <PROJECT>
EOF
```

### Authenticate with Service Identity

* Create a service identity - [GDC reference](https://cloud.google.com/distributed-cloud/hosted/docs/latest/gdch/platform/pa-user/service-identity?hl=en#create_a_service_identity)
* Assign the role bindings to the service identity - [GDC reference](https://cloud.google.com/distributed-cloud/hosted/docs/latest/gdch/platform/pa-user/service-identity?hl=en#assign_a_role_binding_to_the_service_identity)

  The following roles are required:

  * `project-bucket-object-admin`
  * `project-networkpolicy-admin`
  * `project-viewer`
  * `project-vm-admin`
  * `project-vm-image-admin`
  * `backup-creator`

* Create a new key - [GDC reference](https://cloud.google.com/distributed-cloud/hosted/docs/latest/gdch/platform/pa-user/service-identity?hl=en#console_4)
  Store the service private key JSON file (`service_account_private_key_file`), which will be used to generate the CPI configuration file.

### Retrieve Global Trust Bundle

The global trust bundle is required to establish secure TLS connections between different zones in a GDC environment:

```sh
# Add trust-store-viewer role to PA user
kubectl apply -f - <<EOF
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: $PA_USER-trust-store-viewer
  namespace: platform
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: trust-store-viewer
subjects:
- apiGroup: rbac.authorization.k8s.io
  kind: User
  name: $PA_USER
EOF
```

### Create the Ingress Traffic Network Policy

To access workloads from outside the project (e.g., from a BOSH Director), an ingress `ProjectNetworkPolicy` must be created to allow external client IP addresses to access the workloads:

```sh
kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> apply -f - <<EOF
apiVersion: networking.gdc.goog/v1
kind: ProjectNetworkPolicy
metadata:
  namespace: <PROJECT>
  name: allow-ingress-traffic-from-external
spec:
  policyType: Ingress
  subject:
    subjectType: UserWorkload
  ingress:
  - from:
    - ipBlock:
        cidr: <CIDR>
EOF
```

### Create RoleBinding Between Service Account and Bucket-Object Role

```sh
kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> apply -f - <<EOF
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: gdch-bosh-cpi-sa-bucket-role-binding
  namespace: <PROJECT>
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: project-bucket-object-admin
subjects:
- kind: ServiceAccount
  name: <ServiceAccountName>
  namespace: <PROJECT>
EOF
```

### Create Storage Bucket Used for VMM BYO Image Import

```sh
kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> apply -f - <<EOF
apiVersion: object.gdc.goog/v1
kind: Bucket
metadata:
  name: vm-images-bucket
  namespace: <PROJECT>
spec:
  description: "GDC VMM BYO bucket storing raw images of BOSH stemcells"
  storageClass: Standard
EOF
```

### Get Storage Secret JSON File

Using `<ServiceAccountName>` and `<PROJECT>`, retrieve the object storage secret file:

```sh
SECRET_NAME=$(kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> get secret -n $PROJECT -o=jsonpath='{.items[?(@.metadata.annotations.object\.gdc\.goog/subject=="'$ServiceAccountName'")].metadata.name}' | tr ' ' '\n' | grep object-storage-key-std-sa)

kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> get secret $SECRET_NAME -n $PROJECT -o json > sa_storage_secret.json
```

### Get Org Login Config File

Retrieve the `login-config` file:

```sh
kubectl --kubeconfig <ORG_ADMIN_CLUSTER_KUBECONFIG> get configmaps trust-store-root-ext -n $PROJECT -ojsonpath='{.data.ca\.crt}' > trust_store_ca.crt

wget https://console.<orgName>.zone1.google.gdch.test/.well-known/login-config --ca-certificate=trust_store_ca.crt
```

## CPI Configuration

### Generation

Both config JSON and YAML files can be generated by the script [`tools/gen_config_file.sh`](tools/README.md):

Required tools:

* `jq`: [latest version](https://jqlang.github.io/jq/download/)
* `yq`: [latest version](https://github.com/mikefarah/yq/releases)

```bash
bash tools/gen_config_file.sh -lcf <login_config_file> -org <org> -pkf <service_account_private_key_file> -ssf <storage_secret_json_file> -mbus <agent_mbus> -oaef <org_api_endpoint_file>
```

### Properties

#### GDC (`gdch`)

* `org`: Name of the GDC organization.
* `orgAdminURL`: API server URL of the admin/infra cluster of the organization.
* `orgAPIEndpoints`: Map of global and zonal API server endpoints on the GDC org-infra cluster.
* `serviceAccountPKConfig`: Configuration of the GDC service identity private key:
  * `serviceAccountName`: Service account name.
  * `project`: Name of the GDC project the service account is associated with.
  * `tokenUri`: Address of the authentication endpoint.
  * `privateKeyID`: ID of the private key.
  * `privateKey`: Private key PEM content.
* `caData`: Base64-encoded PEM certificate bundle for the GDC API server.
* `storageCredential`: S3-compatible credentials (`accessKeyID` and `accessKey`) used for GDC object storage.

#### Agent (`agent`)

Agent properties passed to the BOSH Agent (`mbus`, `ntp`).

## Development & Testing

### Build CPI

From the repository root:

```bash
make build
```

This compiles `bin/cpi` (Linux amd64) and `bin/cpi_darwin` (Darwin amd64).

### Unit Tests

Run all CPI unit tests from the repository root:

```bash
make test
```

Or run directly with Go:

```bash
go test -timeout=5m ./bosh-cpi/pkg/...
```

### Integration Tests

#### Test Configuration

When running integration tests against a GDC environment using pre-populated GDC golden images, set `"imageProject": "vm-system"` and configure SSH external access ports if running from outside the GDC cluster network:

```json
{
  "gdch": {
    "imageProject": "vm-system",
    "disableSSHProxy": true,
    "externalAccessPorts": [
      {
        "name": "ssh",
        "protocol": "TCP",
        "port": 22
      }
    ],
    "stemcellInfo": {
      "imagePath": "",
      "manifestPath": ""
    }
  }
}
```

Run the integration tests from the repository root:

```bash
go test -v -timeout=50m ./bosh-cpi/integration/... -run "TestMultizone" --configPath=<path_to_config.json>
```

#### Automated GitHub Actions Presubmit

Pull requests that modify CPI code automatically trigger the `Presubmit Integration Test` workflow (`.github/workflows/integration-test.yaml`) against the `cfbosh-staging` GitHub environment.

Maintainers can control presubmit integration test execution via:

* **Commit message directives**:
  * `[skip-cpi-integ]` or `[skip-integ]`: Skips the automatic presubmit integration test run.
  * `[cpi-integ-filter: <FILTER>]`: Overrides the test filter (e.g., `[cpi-integ-filter: TestMultizoneDiskMethods]`).
* **PR comments**:
  * Comment `/test-integration` (or `/test-integration TestMultizoneVMAndDiskMethods`) on a pull request to trigger a run.
* **Manual workflow dispatch**:
  * Trigger `Presubmit Integration Test` from the GitHub Actions tab with an optional `pr_number` and `filter`.
