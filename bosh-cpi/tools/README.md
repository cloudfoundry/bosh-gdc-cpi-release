# `gen_config_file.sh` Script Reference

The `gen_config_file.sh` script is a utility designed to generate BOSH GDC CPI configuration files (in either JSON or YAML format) as expected by the BOSH GDC CPI binary. This configuration file primarily provides the credentials and API endpoints required for the CPI to interact with your GDC environment. This script is useful for quick CPI config mockups (for testing and isolated CPI operations).

## Prerequisites

The script requires the following software to be installed:

* jq: [latest version](https://jqlang.github.io/jq/download/)
* yq: [latest version](https://github.com/mikefarah/yq/releases/latest)

## Usage

```bash
bash tools/gen_config_file.sh -lcf <login_config_file> -org <org> -pkf <service_account_private_key_file> -ssf <storage_secret_file> -mbus <agent_mbus> [-gtb <global_trust_bundle_file>] [-oaef <org_api_endpoint_file>] [-image_project <image_project>] [-disable_ssh_proxy] [-enable_external_access] [-stemcell_path <stemcell_path>] [-use_metadata_server]
```

Vertical format for friendly copy-paste/arg substitution:

```bash
bash tools/gen_config_file.sh \
  -lcf <login_config_file> \
  -org <org> \
  -pkf <service_account_private_key_file> \
  -ssf <storage_secret_file> \
  -mbus <agent_mbus> \
  -gtb <global_trust_bundle_file> # optional \
  -oaef <org_api_endpoint_file> # optional \
  -image_project <image_project> # optional \
  -disable_ssh_proxy # optional \
  -enable_external_access # optional \
  -stemcell_path <stemcell_path> # optional \
  -use_metadata_server # optional
```

## Parameters

The script takes the following parameters:

| Flag / Parameter| Required | Type | Description |
|--|--|--|--|
|`-lcf <login_config_file>`|Yes|Path|Path to the GDCH login configuration file, used to extract `orgAdminURL` and `caData`.|
|`-org <organization_name>`|Yes|String|The name of your GDCH organization (e.g., `org-1`).|
|`-pkf <service_account_private_key_file>`|Yes|Path|Path to the GDCH service account private key JSON file, containing credentials like `serviceAccountName`, `project`, `tokenUri`, `privateKeyID`, and `privateKey`.|
|`-ssf <storage_secret_file>`|Yes|Path|Path to the GDCH object storage secret JSON file, providing `accessKeyID` and `accessKey` for object storage access.|
|`-mbus <agent_mbus_url>`|Yes|URL String|The URL for the BOSH agent's Message Bus (MBUS), specifying how the CPI communicates with the BOSH agent (e.g., `https://user:password@127.0.0.1:4321/agent`).|
|`-gtb <global_trust_bundle_file>`|No|Path|Path to the global trust bundle file (PEM format). If provided, this overrides `caData` from the login config. Used in multi-zone GDCH environments.|
|`-oaef <org_api_endpoint_file>`|No|Path|Path to a JSON file defining GDCH organization API endpoints (`globalAPI` and `zonalAPIs`). Used with  multi-zone deployments. If omitted, single-zone is assumed. See example file format below.|
|`-image_project <image_project_name>`|No|String (testing-only)|The GDCH project where the stemcell image is stored. Defaults to the project in the service account key if omitted. Should be set to `vm-system` if testing with GDCH golden images. Omit if testing with stemcell images.|
|`-disable_ssh_proxy`|No|Flag (testing-only)|If set, `ProxyCommand=none` is added to SSH commands. Used for integration testing from Google Cloudtop.|
|`-enable_external_access`|No|Flag (testing-only)|If set, configures external access for VMs by adding a rule to allow SSH (port 22, TCP) from external sources. Used for integration testing from Google Cloudtop.|
|`-stemcell_path <stemcell_tarball_path>`|No|Path (testing-only)|Path to a BOSH stemcell `.tgz` tarball. The script extracts `image` and `stemcell.MF` from it for `stemcellInfo` in the CPI config. Used for stemcell-related CPI operation testing|
|`-use_metadata_server`|No|Flag|If set, enables the use of a metadata server|

*Example `org_api_endpoint_file.json` content for `-oaef`:*

```json
{
  "orgAPIEndpoints" : {
    "globalAPI": "https://global-api.org-1.google.gdch.test",
    "zonalAPIs": {
      "zone1": "https://management-kube.apiserver.org-1.zone1.google.gdch.test",
      "zone2": "https://management-kube.apiserver.org-1.zone2.google.gdch.test"
    }
  }
}
```

## Output Files

The script generates two files in the current directory:

* `config.json`: The CPI configuration in JSON format.

* `config.yml`: The CPI configuration in YAML format.

These files are directly consumable by the BOSH GDCH CPI binary for isolated testing.

### GDCH CPI config fields not generated by the script

The script doesn't generate every possible CPI field. Fields that are not currently generated are explicitly named below. If required for your specific development or testing scenario, these fields must be manually added to the output `config.json` or `config.yml` files.

| Property | Required | Type | Description |
|--|--|--|--|
|`leaderZone`|No|String|The name of the zone where the BOSH director resides (e.g. `us-east-1a` or `zone1`)|
|`enableHotDiskExpansion`|No|Boolean|When set to true, instructs the CPI to do hot disk expansion when ResizeDisk is called|
|`useTmpDirForSSHKey`|No|Boolean|When set to true, instructs the CPI to use a temporary directory for SSH keys|
|`timeout`|No|Object |A collection of integer timeout values (in seconds) for various CPI operations, such as disk creation or VM deletion. When this property is omitted, the CPI binary will use sensible default values for each operation (okay to omit)|

### Output example

This is an example of a complete BOSH GDCH CPI configuration file.

Inline comments indicate which flag from the `tools/gen_config_file.sh` script sets each field, or
the field must be configured manually.

```yaml
gdch:
  org: "my-org"                                # Set by `-org`.
  releaseVersion: "1.14.2"                     # Manual. Required for features like hot disk expansion.

  # --- Architecture Specific Endpoints ---
  orgAdminURL: "https://..."                   # Set by `-lcf`.
  orgAPIEndpoints:                             # Set by `-oaef`.
    globalAPI: "https://..."
    zonalAPIs:
      us-east1-a: "https://..."
      us-east1-b: "https://..."
  leaderZone: "us-east1-a"                     # Manual. Primary zone for the BOSH director in a multi-zone setup.
  isMultiZone: true                            # Implicitly set by `-oaef` when provided.

  # --- Service Account and Credentials ---
  serviceAccountPKConfig:                      # Set by `-pkf`.
    serviceAccountName: "..."
    project: "..."
    tokenUri: "..."
    privateKeyID: "..."
    privateKey: "..."
  caData: "..."                                # Set by `-lcf`, overridden by `-gtb`.
  storageCredential:                           # Set by `-ssf`.
    accessKeyID: "..."
    accessKey: "..."

  # --- Flags (Feature or Testing-Specific) ---
  useMetadataServer: true                      # Set by `-use_metadata_server`.
  disableSSHProxy: true                        # Set by `-disable_ssh_proxy`.
  useTmpDirForSSHKey: false                    # Manual. (See "GDCH CPI Config Fields Not Generated..." for details.)
  imageProject: "vm-system"                    # Set by `-image_project`.
  externalAccessPorts:                         # Set by `-enable_external_access`.
    - name: "ssh"
      protocol: "TCP"
      port: 22
  stemcellInfo:                                # Set by `-stemcell_path`.
    imagePath: "/path/to/image"
    manifestPath: "/path/to/stemcell.MF"

  # --- Timeouts ---
  timeout:                                     # When omitted by the script, the CPI binary uses its sensible defaults.
    diskCreation: 45
    vmDeletion: 2
    # ... and other timeout fields

agent:
  mbus: "https://user:pass@1.2.3.4:5678"       # Set by `-mbus`.
  ntp: []                                      # Manual. Hardcoded to `[]` by the script.
```
